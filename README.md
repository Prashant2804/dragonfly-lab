# dragonflylab.in

Marketing and lead-generation site for **Aerom**, the survey-grade RTK GNSS system by Dragonfly.

Static HTML generated by a small Node script, plus one serverless function for lead capture.
No framework, no client-side routing, no hydration — every page is a complete HTML document
the crawler sees instantly. That is deliberate: SEO is this site's primary job.

---

## Quick start

```bash
npm install
npm run build      # generates /public
npm run dev        # build + serve on http://localhost:3000
npm run check      # build + verify every page in a real browser (exits non-zero on failure)
```

`npm run check` is the gate. It renders every page in Chromium and fails the build if a page
has a console error, a missing or over-long title, a missing canonical, more than one `<h1>`,
invalid JSON-LD, a dead internal link, an image without alt text or explicit dimensions, or a
broken lead API. Run it before every deploy.

## Deploying to Vercel

1. Push this folder to a Git repository.
2. In Vercel, **Add New → Project**, import the repo.
3. Framework preset: **Other**. Vercel reads `vercel.json`, so build command and output
   directory are already configured (`npm run build` → `public`).
4. Add the environment variables below.
5. **Settings → Domains** → add `dragonflylab.in` and `www.dragonflylab.in`, and point your
   registrar's nameservers or A/CNAME records at Vercel as it instructs.
6. Deploy.

`/api/lead.js` is picked up automatically as a serverless function — no configuration needed.

## Environment variables

Set these in **Vercel → Project → Settings → Environment Variables** (Production *and* Preview).
Every integration is optional, but **at least one must work** or the form will show visitors an
error rather than silently swallowing their enquiry. That is intentional.

| Variable | Needed for | Notes |
|---|---|---|
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | Google Sheet | `something@project.iam.gserviceaccount.com` |
| `GOOGLE_PRIVATE_KEY` | Google Sheet | The whole `-----BEGIN PRIVATE KEY-----` block. Paste it with real newlines; `\n` escapes also work. |
| `GOOGLE_SHEET_ID` | Google Sheet | The long id in the sheet's URL between `/d/` and `/edit` |
| `GOOGLE_SHEET_TAB` | Google Sheet | Optional, defaults to `Leads` |
| `APOLLO_API_KEY` | Apollo.io | From Apollo → Settings → Integrations → API |
| `RESEND_API_KEY` | Email alerts | From resend.com — free tier is plenty |
| `NOTIFY_EMAIL` | Email alerts | Where new-lead alerts go |
| `NOTIFY_FROM` | Email alerts | A verified sender, e.g. `leads@dragonflylab.in` |

### Setting up the Google Sheet (10 minutes, once)

1. Create a new Google Sheet. Name the first tab **Leads**.
2. Put these headers in row 1, in this order:

   `Timestamp (IST)` · `Intent` · `Use case` · `Name` · `Organisation` · `Email` · `Phone` ·
   `City / Country` · `Message` · `Marketing consent` · `Source page` · `Referrer` · `UTM`

   The **Marketing consent** column is the one that matters legally: only send product
   updates to rows that say `yes`. Replying to someone's enquiry needs no opt-in; emailing
   them about anything else does.

3. Go to [console.cloud.google.com](https://console.cloud.google.com) → create a project →
   **APIs & Services → Enable APIs** → enable **Google Sheets API**.
4. **Credentials → Create credentials → Service account.** Create it, then open it →
   **Keys → Add key → JSON**. Download the file.
5. From that JSON take `client_email` and `private_key` — those are the two variables above.
6. **Share the Google Sheet with the `client_email` address**, with Editor access. This step is
   the one everybody forgets; without it every write returns 403.

The sheet *is* your lead database. **File → Download → Microsoft Excel (.xlsx)** any time you
want it as a spreadsheet.

## Project layout

```
build.mjs                 the static site generator
vercel.json               build config, security headers, cache rules, redirects

api/
  lead.js                 the only backend endpoint — Sheets + Apollo + email fan-out

src/
  data/
    site.mjs              global config, nav, use-case list, the proof figures
    compare.mjs           SINGLE SOURCE OF TRUTH for competitor claims
    solutions.mjs         the four use-case pages, as data
  templates/
    layout.mjs            HTML shell: head, SEO meta, JSON-LD, header, footer
    blocks.mjs            reusable sections: router, proof, comparison, FAQ, forms
  pages/                  one module per page
  assets/
    styles.css            the design system
    app.js                nav + form behaviour (~4 KB, no dependencies)
    viewer.js             the 3D product viewer (loads lazily, degrades silently)

scripts/
  render-stills.mjs       renders the GLB models to hero PNGs — re-run when CAD changes
  serve.mjs               local dev server, runs the real API in-process
  check.mjs               pre-deploy verification

static/                   copied verbatim into /public
  models/*.glb            web-ready 3D models generated from the FreeCAD files
  img/*.png               rendered stills

public/                   BUILD OUTPUT — never edit by hand, it is wiped every build
```

## Editing content

**Change a competitor figure** → `src/data/compare.mjs`. It feeds the homepage table, the
compare page and all four solution pages at once. **Bump `verifiedOn` when you check the
figures.** Re-verify quarterly; a comparison table with stale competitor data discredits every
other claim on the site.

**Change a use-case page** → `src/data/solutions.mjs`. All four share one template, so
edit the data, not the layout.

**Post a company update** → `src/pages/company.mjs`, add to the top of the `updates` array.

**Change the price gate copy** → `src/pages/pricing.mjs`.

**Add a page** → create `src/pages/whatever.mjs` returning `{ url, title, description, body, schema }`
and add it to the `pages` array in `build.mjs`. It lands in the sitemap automatically.

**Update the 3D models** → replace `static/models/*.glb`, then run
`node scripts/render-stills.mjs` to regenerate the hero images.

## Security and legal

See **`SECURITY-AND-COMPLIANCE.md`** for the full review: what was found and fixed, what is safe
by design, the risks knowingly accepted, and the legal checklist.

Two things there need action from you before launch:

1. Fill in the four `TODO` placeholders in `src/data/site.mjs` → `legal` (registered entity name,
   registered address, Grievance Officer, privacy email). The privacy policy is materially weaker
   coming from a vaguely-identified entity.
2. Have a lawyer read `/privacy/` and `/terms/`. They are carefully drafted against the DPDP Act
   2023, the DPDP Rules 2025 and GDPR — but drafted by an engineer, not a lawyer.

**Do not add GA4 or Clarity casually.** The site currently sets no cookies, which is why it has no
consent banner. Both of those set cookies and would require one for EU visitors — on a site whose
entire job is conversion. Search Console gives you query data for free without cookies.

## Claims discipline

This site sells a precision instrument to engineers. Its credibility is the asset. Three rules,
enforced by convention rather than code — please keep them:

1. **Never claim better accuracy than the incumbents.** Published RTK accuracy across this
   market is ~7–8 mm + 1 ppm. Aerom's ~1 cm is *demonstrated on our own hardware under good sky
   view* and is always described that way. Same class, not better.
2. **Keep the losing row in the comparison table.** Tilt compensation is not shipped. A table
   where one company wins every row reads as marketing and discredits the rest.
3. **Roadmap items are labelled as roadmap.** NavIC, tilt, Aerom Studio, IP rating. If it is not
   in a user's hands, it does not get described as a feature.

## After launch

- Verify the domain in **Google Search Console** and submit `/sitemap.xml`.
- Do the same in **Bing Webmaster Tools** — it is five minutes and it also feeds other engines.
- Ahrefs Web Analytics is already installed via `site.ahrefsKey` in `src/data/site.mjs`.
- To add GA4 or Microsoft Clarity, set `ga4Id` / `clarityId` in the same file. The build omits
  the tags entirely when they are empty, so there is no cost to leaving them blank.
- Watch Search Console's Queries report. Within a few weeks it will tell you what people
  actually search to reach you — better data than any keyword tool, and free.
