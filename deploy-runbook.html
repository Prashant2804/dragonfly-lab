Taking dragonflylab.in live

Eighteen steps, in order, from the code on your machine to a site Google can find. Tick them off as you go — your progress is saved in this browser.

0 / 18

Four things to settle before the site is public

None of these block a preview deployment — do the whole runbook today. They block the moment you send the link to a customer.

  • A phone number. For Indian B2B capital equipment it is the first trust signal checked. Goes in src/data/site.mjs.
  • An email on the domain. A gmail.com address selling a lakh-plus instrument undercuts everything else on the page.
  • Warranty, lead time and service turnaround. The values in src/data/commerce.mjs are placeholders, and they are promises to customers.
  • Legal entity name and address. Four TODOs in site.mjs → legal. A privacy policy from a vague entity is a weak privacy policy.
Phase 1

Get the code onto GitHub

Vercel deploys from a Git repository and redeploys on every push. The repo already has commits on a main branch, so this is just adding a remote.

01

Create an empty private repo

On github.com/new, name it dragonflylab. Do not add a README, .gitignore or licence — the project already has them, and an initialised repo makes the first push conflict.

02

Push it

Unzip the project, open a terminal inside the dragonflylab folder, and run this with your own username.

# from inside the dragonflylab folder
git remote add origin https://github.com/Prashant2804/dragonflylab.git
git push -u origin main

GitHub will ask for a Personal Access Token, not your password — create one at Settings → Developer settings → Personal access tokens with repo scope.

Phase 2

Deploy on Vercel

03

Import the repository

At vercel.com/new, sign in with GitHub and import dragonflylab.

04

Set the framework preset to “Other”, then change nothing else

Build command and output directory are already declared in vercel.json (npm run build → public). Overriding them in the dashboard is the most common way this goes wrong.

05

Deploy, and open the preview URL

About a minute. You get a dragonflylab-….vercel.app address. Click through every page. The form will fail at this point — that is expected, nothing is connected yet.

Vercel's free Hobby plan is for non-commercial personal use only. A company website is commercial, so this needs the Pro plan at $20 per user per month. There is a free Pro trial to get started. If you would rather not pay yet, Cloudflare Pages permits commercial use on its free tier — but the lead API would need rewriting for its runtime, so it is a real decision, not a toggle.
Phase 3

Connect the lead pipeline

Three destinations, all optional individually — but at least one must work, or the form shows visitors an error instead of silently swallowing their enquiry. That is deliberate.

06

Create the leads spreadsheet

New Google Sheet, first tab named Leads, with these headers in row 1:

Timestamp (IST) | Intent | Use case | Name | Organisation | Email |
Phone | City / Country | Message | Marketing consent | Source page |
Referrer | UTM

Only email people whose Marketing consent cell says yes. Replying to an enquiry needs no opt-in; anything else does.

07

Make a Google service account

At console.cloud.google.com: create a project → APIs & Services → enable Google Sheets API → Credentials → Create credentials → Service account → open it → Keys → Add key → JSON. From the downloaded file you need client_email and private_key.

Then share the Sheet with that client_email address, as Editor. This is the step everyone forgets, and without it every write returns 403. Share only this sheet with it — that account can reach anything you share with it.
08

Get the email and Apollo keys

Resend — sign up at resend.com, verify dragonflylab.in as a sending domain, create an API key. This is what alerts you within seconds of a lead arriving, which is most of the value.

Apollo — Settings → Integrations → API. Leads land as contacts so a follow-up cannot get lost.

09

Add the variables, then redeploy

Vercel → Settings → Environment Variables. Tick both Production and Preview for each.

VariableWhat it is
GOOGLE_SERVICE_ACCOUNT_EMAILThe client_email from the JSON key
GOOGLE_PRIVATE_KEYThe whole -----BEGIN PRIVATE KEY----- block, newlines and all
GOOGLE_SHEET_IDThe long id in the Sheet URL, between /d/ and /edit
GOOGLE_SHEET_TABOptional. Defaults to Leads
APOLLO_API_KEYFrom Apollo
RESEND_API_KEYFrom Resend
NOTIFY_EMAILWhere new-lead alerts go — your phone's inbox
NOTIFY_FROMA verified sender, e.g. leads@dragonflylab.in

Environment variables only take effect on a new build: Deployments → ⋯ → Redeploy.

Phase 4

Point the domain

10

Add both hostnames in Vercel

Settings → Domains → add dragonflylab.in and www.dragonflylab.in. Set the bare domain as primary so www redirects to it — every canonical URL in the site is written without www, and disagreeing with that splits your ranking signals across two addresses.

11

Change the DNS at your registrar

Wherever you bought dragonflylab.in. Vercel shows the exact values — the two usual routes are:

# simplest — hand DNS to Vercel
nameservers:  ns1.vercel-dns.com
              ns2.vercel-dns.com

# or keep your existing DNS provider
A      @      76.76.21.21
CNAME  www    cname.vercel-dns.com

Confirm the current values in Vercel's dashboard rather than trusting this from memory — they do change.

12

Wait for propagation, then check HTTPS

Usually minutes, occasionally a few hours. Vercel issues the TLS certificate automatically once DNS resolves. The site sends a two-year HSTS header with preload, so once it is live over HTTPS, browsers will refuse plain HTTP for this domain — make sure you are happy with the domain before this sets.

Phase 5

Prove it actually works

A form that looks fine and silently drops enquiries is worse than no form. Test it on the live domain, not the preview.

13

Submit a real enquiry to yourself

Then confirm all three: a row appears in the Sheet, a contact appears in Apollo, and the alert email arrives. If the email is the only one missing, you still have the lead — that is why there are three.

14

Send yourself the link on WhatsApp

Check the preview card renders with the product image and headline. Survey WhatsApp groups are how this spreads in your market, so the card matters more here than the homepage hero does.

15

Open it on a real mid-range Android on mobile data

Not the desktop responsive simulator. Most of your visitors arrive this way, and it is the only honest test of whether the 3D and the images are as light as they measure.

Phase 6

Get found

16

Verify Google Search Console and submit the sitemap

At search.google.com/search-console, add dragonflylab.in as a Domain property and verify with the TXT record it gives you. Then submit:

https://dragonflylab.in/sitemap.xml

Search Console is also where your free keyword data comes from — real queries people used to reach you, which beats guessing.

17

Add Bing Webmaster Tools

It imports straight from Search Console in two clicks. Small traffic share, zero extra effort, and it also feeds several AI search products.

18

Confirm Ahrefs Web Analytics is receiving

The tag is already on every page. Check your Ahrefs dashboard shows the visit. It is cookie-free, which is exactly why this site needs no consent banner — adding GA4 or Clarity would set cookies and change that.

After launch

To change anything: edit, commit, push. Vercel rebuilds and redeploys on its own. Run npm run check first — it renders every page in a real browser and fails on console errors, broken links, missing meta, CSP violations and a broken lead API.

Quarterly: re-verify the competitor figures in src/data/compare.mjs and bump verifiedOn. A comparison table with stale data discredits every other claim on the site.

Every month or so: post an update on the Company page. It is the cheapest signal that the company is alive, and it is the page a cautious buyer checks.

Within 36 months: delete old leads. The privacy policy promises it.
